# PhysQuest

Retro-style sports science RPG: pure canvas game, no game framework and no UI framework.

## Architecture

- **Entry**: `main.ts` loads the console CSS and calls `startGame()` in `game.ts`, which wires every scene, the pause menu, autosave/auto-pause on `visibilitychange`/`pagehide`, and the debug hook.
- **Console shell** (`src/ui/`): a CSS-built handheld around the screen. `mountConsole()` builds the DOM (`consoleDom.ts`), solves the portrait and landscape layouts screen-first (`consoleLayout.ts`: thin bezel, brand row only when there is height to spare, controls never under 44px) and wires Pointer Events for every button (`consoleInput.ts`). The game draws into an off-DOM 256x224 canvas; `present()` copies each frame to the display canvas at an integer multiple (sharp-bilinear when the fit is fractional).
- **Engine**: `GameLoop` (fixed 60 Hz updates, renders only after an update and at most once every `renderEvery` updates, keeps running after a thrown frame, schedules nothing while the page is hidden), `Input` (keyboard + console buttons), `SceneManager`. Rendering budget (`game.ts`): touch devices (`pointer: coarse`) render at 30 fps, every device at 20 fps after 10 s with no button pressed or held, and the boss scene always at 60; updates and timers never change. `frameWatch.ts` hashes every call on the game context, so a frame identical to the last is not presented (at least one present a second); it relies on every scene clearing the screen first and on offscreen canvases being painted once (caches), so never repaint a cached canvas in place. Draw small icons from cached canvases, not a `fillRect` per pixel.
- **Rendering**: imperative canvas calls. `PixelFont` (5x7 font, cached glyph canvases), `SpriteSheet` (cached sprites), `TileMap` (whole maps pre-rendered per palette), `DialogueBox`, `OverworldHud`, `Palettes`.
- **Scenes**: `TitleScene` → `IntroScene` (name entry first, then one line by name) → `LevelSelectScene` → `OverworldScene` (hub + 4 rooms, + the ATHLETE room in Distance Running) → `RoomChallengeScene` → `BossBattleScene` → `LevelClearScene`.
- **The player** is a sport scientist addressed by the name typed at name entry, never "Coach": game text writes `{NAME}`, filled at render time with the button tokens (`engine/nameToken.ts` via `fillButtonNames`, so dialogue, `input.fill()` and `announce()` all fill it; ALAN is said "Alan").
- **Performance Director and ATHLETE room** (levels with `meetContentFor(level)`, Distance Running so far, in a visit that plays the redesigned rooms: `loader.ts meetRoomFor`, copied into `GameState.meetRoom` when the level starts): the hub is `data/rooms/hub.ts` (Director NPC `hub_director`, a fifth door ATHLETE at (3,12), `data/meetDoor.ts`; Aisha is not in the hub). The Director's welcome starts by itself on the first hub entry (by name; remembered per level in `GameState.meet`, saved), later talks give the reminder or after lines. The ATHLETE room (`meet` map id, `src/rooms/meet/`, `data/rooms/meet*.ts`, tiles 500-599) comes before TESTING (`roomUnlocked`, `nextDoor`, `roomsTotal` = 5, arena needs all five); it scores OVERVIEW n/asks (best kept in `GameState.meet`) and never touches the four stats, `roomProgress` or `showdownRating`. Content: `src/rooms/content/meet-running.ts` (`MeetContent`). A classic visit (other levels, `?rooms=classic`, chunk late or failed) has none of it and plays exactly as before.
- **Playable sports**: only the levels in `PLAYABLE_LEVELS` (`data/levels.ts`; Distance Running only for now) can be picked. The level select shows the others greyed as COMING SOON and its cursor skips them; the game is complete once every playable sport is cleared (`allPlayableCleared`). The debug hook's `playLevel(n)` still starts any level.
- **Redesigned rooms** (`src/rooms/`): levels in `REDESIGNED_LEVELS` (`rooms/preview.ts`; Distance Running so far) play an *instrument* per room instead of the classic question lists. `RoomChallengeScene` asks `instrumentFor(room, level)` and hands it a `RoomHost` (`rooms/types.ts`: say/sayAll/quit/complete, firstVisit/rulesRead, input, dialogue); the scene keeps the header, sport plate, pause menu, stat and completion line. Each room is `src/rooms/<testing|datalab|training|analysis>/` (a pure model unit-tested in `tests/`, plus renderers) and its map in `src/data/rooms/<room>*.ts` (tiles registered with `registerTiles`, ids 100-199/200-299/300-399/400-499 by room; `life` animation on a dt room clock; `talk` lines; `npcFloor`; `describe` for screen readers), picked by `mapFor(mapId, level)`. `?rooms=classic` switches a browser back to the classic rooms (`?rooms=new` undoes it). The rooms' code, maps and art are their own chunk (`rooms/bundle.ts`), loaded by `rooms/loader.ts`: preloaded right after the title appears, and awaited (with LOADING on the level select, for 3 s at most) before a redesigned level starts. Each level visit is fixed when it starts (`commitLevel`): if the chunk was not ready the whole visit plays the classic rooms; a failed load stays failed until the page reloads.
- **Systems**: `Movement`, `Collision`, `Dialogue`, `BossMinigame`, `PauseMenu`, `SaveSystem`, `SupportScores` (score names, showdown focus, TARGET).
- **Audio**: `audio/Sfx.ts` synthesises chiptune blips with Web Audio (no files); unlocked on the first gesture; mute persisted.
- **Director check-ins** (redesigned Distance Running visits, `meetRoom`): after the ATHLETE room the Performance Director's needs chat, and after the first completion of each room a check-in (`systems/CheckIns.ts` builds the lines from `MeetContent.needs`/`checkIns`; `OverworldScene` runs them), must be read to the end before the next room or the ARENA opens (`checkInDue`, `roomUnlocked`, `arenaOpen`, `nextStop` in `GameState`; `meet[level].needs`/`heard`/`tests`/`call`, save v4). Back in the hub with one due it starts by itself; B leaves it unheard. The Testing Lab ends at its printout: the check-in gives the verdict. The Testing Lab runs a battery of 2 tests (`RoomResult.testing.tests`, kept in `meet.tests`); the Data Lab gets one file per test that has one (`host.tests`: lactate profile stages, critical speed trials) and offers only those files' variables, and the Training Floor drops numbers from an untested file. A battery with no file sends the player back (`retestDue`: DATA, and the ARENA, stay shut until TESTING is run again; the re-test's check-in comes again). No screen shows a value from a test that was not run.
- **State**: single `GameState`. The active level's rooms and stats live in `roomProgress`/`playerStats` (keys `speed`/`strength`/`endurance`/`power`, one per room in order, kept for the save format; players see them as support scores: TEST CHOICE, DATA INSIGHT, TRAINING PLAN, EVALUATION from `SCORE_LABEL`, never as athlete qualities); unfinished levels are stashed in `levelProgress` (`stashLevel`, `activateLevel`, `clearActiveLevel`). `returnDoor` puts the player back outside the hub door they used.

## Key Patterns

- Scenes are factory functions `createXScene()` returning `{ update, render, onEnter?, onExit? }`.
- Input: call `input.read()` exactly once per update. Use the edge fields (`aPressed`, `bPressed`, `startPressed`, `selectPressed`, `upPressed`...) for presses, `upRepeat`/`downRepeat`/`leftRepeat`/`rightRepeat` for menu cursors (auto-repeat), and held fields (`a`, `up`...) only for holds. Presses are latched between reads, so never add local "wasDown" debouncing. `input.blockRepeats()` stops an already-held direction auto-repeating until it is released; it runs on every scene switch, when a choice list appears and when the pause menu opens, so call it for any new menu. Name entry uses `input.setTextMode(true)` so physical keys type letters.
- Buttons: A confirms/interacts and advances dialogue; B leaves any conversation at once (the dialogue's `onCancel`, else it just closes; a room challenge left this way records nothing and keeps the player in the room), goes back or deletes, and runs while held; START opens the pause menu in levels (confirms on menus); SELECT opens the objectives panel.
- Button names in game text follow the player's device: write `{A}`, `{B}`, `{START}`, `{SELECT}` or `{DPAD}` and fill them with `input.fill()` (or `input.label(button)`) at render time; dialogue text and choices are filled automatically. Keyboard players then see SPACE/X/ESC/SHIFT/ARROWS, touch players A/B/START/SELECT/D-PAD. Never hard-code a button name in a prompt.
- Who is talking: a character's line passes `speaker` in the dialogue options (`athleteSpeaker(level)`, `DIRECTOR_SPEAKER`, `rivalSpeaker(level)` from `data/speakers.ts`). It gets a name tab on the box's top edge and a frame in the speaker's colour, and screen readers hear "Name: text". Narration, rules, prompts, notes and results pass no speaker and keep the plain box. Never write "Aisha says:" or quotes into the text itself.
- Dialogue options (`dialogue.show(..., options)`): `exitLabel` names what B does in the box's hint ('' hides it), `nextLabel` what A does on the last page (e.g. READY before a bout), `lock` ignores A and B for a moment (used after bouts so a carried-over mash can't skip a result).
- In-level scenes start `update()` with `if (pauseMenu.handle(dt, inp)) return;` and draw `pauseMenu.render(ctx)` last. The pause menu's QUIT TO TITLE asks first ("This attempt won't be saved.") while a room is still being played; finished rooms are always saved.
- No `setTimeout`/`setInterval` in game logic: timers advance with `dt`, so pausing freezes them. `Date.now()` is only for cosmetic blinking.
- Rooms are taken in order (`roomUnlocked`, `nextRoom`, `nextStop`): locked doors refuse with a reason (`checkIns.doorRefusal` when the Director is waiting), the hub arrow points at the next door (or the Director while a check-in is due), and the objectives panel shows locks. Finished rooms stay open for replays.
- Dialogue choices are shuffled per prompt, multi-select rooms remove picked options, and replayed rooms keep the best stat.
- Showdown rating = 70% of the level's focus score + 30% of the mean of all four (`showdownRating`). The focus is `showdownFocus(level)` (Distance Running: TRAINING PLAN; classic levels: their `bossStat`); the bout type is `boutType(level)` (Distance Running: RACE TO THE LINE, `systems/RaceModel.ts` + `RaceView.ts`: a compressed 5000 m where Aisha sits on the rival's pace (A up) and a KICK gauge sized from the rating stands for her D′, refilling only below critical speed; the rival runs even laps and a 72 s last lap; classic levels follow `bossStat`), and the rival's TARGET comes from `showdownTarget`. Winning the case ends in the hub with Aisha's race result and Dr Ellis's Phase 4 debrief (`systems/Finale.ts`, lines in `rooms/content/finale-running.ts`, played by `OverworldScene.queueTalk`); the rooms and scores are kept. The Distance Running hub's SUPPORT BOARD (`render/SupportBoard.ts`, A on the wall top left) shows the four scores, the OVERVIEW, the rating, the TARGET and the ARENA's status; Dr Ellis's board lines are in `rooms/content/board-running.ts`. The boss scene warns before the fight when the rating cannot beat the rival's target, and a rules card (two pages the first time a bout type comes up in a session, one line after) gates every countdown. The rival's number is always called TARGET. A defeat says why: rating too low, no A presses at all (`BoutResult.idle`), or a tip for the bout type.
- `saveGame()` also stashes the active level. It runs after name entry, every room, every showdown, the Director's welcome, needs chat and check-ins, from the pause menu, and when the page is hidden mid-level. The save format is versioned (v3 adds `meet`, the per-level welcome and athlete meeting; v1 saves migrate with none; a v2 level already under way counts as met, unscored; v4 adds the Director's needs chat and check-ins, and older saves count the needs chat and every finished room's check-in as heard).
- `ui/announce.ts` mirrors dialogue into an aria-live region for screen readers; lines announced in the same moment are read together.
- Instruments (redesigned rooms) never call `input.read()`: they get the step's input and a `dialogueBusy` flag (don't act on presses while it is true), keep logic in a pure model with an injectable rng, draw only between y 38 and the dialogue box (`rooms/frame.ts` `STAGE`), use `drawPromptBox`/`drawOptionList` from `DialogueBox` for game-style boxes and lists, ignore A/B for 0.35 s on each new decision, ask LEAVE? (STAY/LEAVE) before B would lose decisions, call `host.rulesRead()` once the full rules have been read, and allocate nothing per frame.

## Build, Test & Deploy

- `npm run dev`: Vite dev server
- `npm run build`: `tsc -b && vite build` → `dist/`
- `npm test`: vitest unit tests in `tests/` (room models, scoring bands, layouts, content consistency with `sports.ts`)
- Debug hook: on the dev server, or any build opened with `?debug`, `window.__pq` exposes `{ state, scene(), go(sceneId), enterRoom('room1'..'room4' or 'meet'), playLevel(n), showRoom('hub', 'room1'.., 'meet'), instrument(), input, dialogue, pauseMenu, sfx, frames() }` (`frames()`: the loop's update, render and present counts) for automated playthroughs (e.g. Playwright with WebKit/Chromium device emulation). It appears only once the redesigned rooms' chunk has loaded, so scripts can start a level and enter a room straight away (a script that stops time must let that load finish first). Any automated browser (`navigator.webdriver`) plays at zero volume, with or without `?debug`.
- `npm test` includes `tests/shell/`, which drives the real `RoomChallengeScene`, dialogue and pause menu (`tests/shell/harness.ts`); `FUZZ_SEEDS=400 npx vitest run tests/shell` runs the long random-input soak.
- Deployed on Vercel (auto-deploy on push to `master`).

## Game Content

4 levels, each with a sport, athlete and rival boss. Each level has 4 rooms (test selection, variable ID, training prescription, performance prediction). The player first meets the athlete in the ATHLETE room (Phase 1 athlete overview from Alan's paper, `docs/reference/scientific-support-process.txt`; content in `src/rooms/content/meet-running.ts`). The sports-science content is in `src/data/sports.ts` (maps, dialogue, sprites and level names are in the other `src/data/` files); the redesigned rooms' extra content is in `src/rooms/content/<sport>.ts`, used verbatim; `docs/rooms.md` documents rooms, scoring and bosses. Physiology content (numbers, correct answers, explanations) is reviewed by Alan: ask before changing it. The Distance Running rooms' content was approved for release and is open for team review: `docs/content-review.md` lists what is provisional and links the review page; apply answers from there verbatim.
